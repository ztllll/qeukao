# 部署与使用手册

> 普通用户请先看根目录 [README](../README.md) 的「三步上手」：直接用 Releases 里的 `QeukaoServer.exe`，不需要装 Python。本文是完整说明，第 2 节是从源码运行的方式。事实源是代码；与代码不一致时以代码为准。接口与协议细节见 [windows-contract.md](windows-contract.md)。

## 1. 组成

| 部分 | 运行在 | 说明 |
| --- | --- | --- |
| 服务端 | 管理员的 Windows 电脑 | Python 3.9+（仅标准库）。`server_gui.py` 是 tkinter 控制面板，启动后在后台线程运行 HTTP 服务；业务与 Web 管理端都在这个服务里 |
| 客户端 | 每台教室电脑（Windows + Chrome） | Go 编译的单个 exe，无窗口、托盘右键退出、开机自启、崩溃自动重启。收到服务端指令后弹窗，点「确定」后打开 Chrome 访问填报页 |
| Web 管理端 | 管理员浏览器 | `http://服务端IP:端口/admin`，输入管理密码进入；数据（当前场次 + 筛选 + 可视化 + 明细 + 验收）、下发（含客户端状态）、客户端管理、日志、设置（含基本信息） |

客户端**主动连服务端**（长轮询），教室电脑不需要开放任何入站端口。

## 2. 服务端安装与启动

**推荐：直接双击 Releases 里的 `QeukaoServer.exe`**（数据放在 exe 旁边的 `data\` 目录）。下面是从源码运行的方式。

1. 安装 Python 3.9+（官方安装包，勾选 *tcl/tk* 与 *Add python.exe to PATH*）。
2. 把整个项目目录复制到服务端电脑（需要 `app.py`、`qk_*.py`、`server_gui.py`、`static/`、`client/dist/qeukao-client-template.exe`）。
3. **放行端口**：右键 `open_firewall.bat` →「以管理员身份运行」（默认放行 TCP 8000；改了端口则 `open_firewall.bat 端口号`）。
4. 双击 `start_server.bat`（有控制台，便于看报错）或 `run_server.pyw`（无控制台，出错写 `%LOCALAPPDATA%\QeukaoServer\gui-error.log` 并弹窗）。
5. 控制面板里能看到 **访问地址**（本机所有局域网 IPv4 的填报地址与管理地址，可复制/打开）、服务状态、端口、数据库备份/导入导出、Web 管理密码、教室识别规则、客户端生成。

> 关闭控制面板窗口会停止服务，所有客户端随即离线。

## 3. 配置与数据位置

默认都在项目目录下（可用环境变量改）：

| 项 | 默认位置 | 说明 |
| --- | --- | --- |
| 配置 | `data/config.json` | 端口、监听地址、管理密码哈希、会话密钥、接入密钥、教室识别规则、备份策略。**密码不放数据库**，所以导入旧数据库不会把密码回滚 |
| 数据库 | `data/qeukao.sqlite3` | SQLite（WAL） |
| 备份 | `backups/` | 可在面板里改目录。文件名 `qeukao-db-时间[-标记].sqlite3` |

| 环境变量 | 作用 |
| --- | --- |
| `QEUKAO_DATA_DIR` | 数据目录（含 config.json 与默认数据库） |
| `QEUKAO_DB` | 数据库文件路径 |
| `QEUKAO_HOST` / `QEUKAO_PORT` | 覆盖配置里的监听地址/端口 |
| `QEUKAO_ADMIN_PASSWORD` | 仅当配置里还没有密码哈希时作为初始密码；在面板或 Web 设置里改过密码后以哈希为准 |
| `QEUKAO_SESSION_SECRET` | 会话签名密钥（缺省时首次启动随机生成并写入配置） |
| `QEUKAO_EXCEL_IMPORT_DIR` / `QEUKAO_EXCEL_IMPORT_FILE` | Excel 导入目录/文件。缺省依次探测 `%USERPROFILE%\Desktop`、`...\OneDrive\Desktop`、`~/桌面`、`~/Desktop` |
| `QEUKAO_CLIENT_TEMPLATE` | 客户端模板 exe 路径（缺省依次找程序目录旁的 `client/dist/qeukao-client-template.exe`，打包成单文件 exe 时再找包内同路径） |

### 管理密码

- **默认密码是 `112233`，首次登录后台必须先改密码**：还在用默认密码时，后台除「设置新密码」外的所有接口都返回 403（`MUST_CHANGE_PASSWORD`），改完才能使用；新密码不能还是 112233（网页和控制面板都会拒绝）。用环境变量 `QEUKAO_ADMIN_PASSWORD` 指定了初始密码的部署不受此限制。
- **只有一个密码：管理端登录密码。** 登录后台后，改/删记录、验收、Excel 导入、改基本信息、下发都**不再重复输密码**（危险操作靠后台的二次确认弹窗，登录会话 8 小时过期）。前台（填报页）没有任何管理入口，老师只能填报，提交后不能改；改错了由管理员在后台改。
- 修改入口：控制面板「Web 管理密码」，或管理端「设置 → 修改管理密码」（需旧密码，4–64 个字符）。
- **配置文件损坏时认证会锁定，而不是退回默认密码**：`data/config.json` 若不是合法 JSON（例如被手工改坏），服务端会把坏文件改名保留为 `config.json.bad-<时间>`，新建一份配置并把 `passwordLocked` 置为 true——此时 Web 登录一律拒绝（登录页提示"配置文件曾损坏，管理密码已锁定"），`QEUKAO_ADMIN_PASSWORD` 也无效。恢复方法：在服务端控制面板「Web 管理密码」重设密码（只有本机面板能解除锁定）。损坏前的密钥与密码哈希在 `.bad-*` 文件里，需要时可手工合并回来。
- 记事本等另存为「带 BOM 的 UTF-8」不算损坏，内容不变就照常读取。
- 例外（有意保留）：`config.json` **整个文件被删除**视为首次运行——会重新生成配置，密码回到默认 `112233`，接入密钥也会重新生成（已分发的客户端全部失效，需重新生成分发）。别随手删这个文件。

## 4. 生成并安装客户端

1. 控制面板点「生成绑定客户端…」，或管理端「客户端 → 下载绑定客户端」。得到的 exe 已内置：服务端地址列表、接入密钥、服务端名称。
2. 把 exe 拷到教室电脑，**双击运行一次即可**：它会把自己安装到 `%LOCALAPPDATA%\QeukaoClient\`、写入当前用户开机自启（`HKCU\...\Run`）、转入后台运行。之后没有窗口，任务栏托盘有图标，右键「退出」。
3. 客户端连上后出现在管理端「客户端」页。**同一个 exe 可以拷给所有教室**，教室由服务端按客户端的 IP 判断，不是每个教室一个 exe。
4. 「重置接入密钥」会让所有已分发的客户端失效，需要重新生成并分发。
5. **教室机最低系统：Windows 10 / Windows 11**（客户端用 Go 1.22+ 构建，Go 1.21 起不再支持 Win7/8/8.1，exe 在旧系统上无法启动；请在分发前确认教室机均为 Win10/Win11）。**服务端电脑可以是 Windows 10/11 或 Windows Server 2016 及以上**（Python 3.9+ 与 tkinter，在 Server 上需要桌面体验，Server Core 没有 GUI 不适用；防火墙放行用 open_firewall.bat 同样适用）。
6. 重新分发新绑定的 exe（例如换了接入密钥或服务端 IP）：在教室机上再双击运行一次即可。如果旧客户端正在运行，新 exe 会把已安装的文件让位改名为 `.old` 后复制过去，**新配置在客户端重启（或下次开机登录）后生效**；也可以在托盘右键「退出」后重新双击新 exe。
7. 管理端可对单个客户端「拉黑」或「删除」。

客户端的数据/日志在 `%LOCALAPPDATA%\QeukaoClient\`（`client-id`、`client.log`，超过 1MB 轮转一次）。

### 基本信息（后台配置，存放在 config.json 的 site 段）

- `orgName`：单位名称（填报页和统计表抬头；首次安装为空，后台会提示先填写），`orgAddress`：地址（统计表页脚），`roomCount`：教室数量（1–500），`roomNames`：教室名称（留空 = 自动生成），`roomNotice`：填报页选教室时的提醒语（可留空，最多 80 字）。接口：`GET /api/site`（公开，只读）、`POST /api/admin/site`（需登录）。
- 管理员改已提交的教室数据：`PUT /api/admin/current-reports/<教室名>`（需登录）。老师提交过的教室再次提交一律 409。

- 数据分析接口：`GET /api/admin/analytics`（需登录）。参数 `title`（标题模糊匹配，包含即可，`%` `_` 当普通字符）、`from` / `to`（考试日期范围，含两端，YYYY-MM-DD）、`room`（可选，返回该教室历次记录）。「一次考试 = 同一标题 + 同一考试日期」。返回 `totals`、`exams`（每场的教室数/应到/实到/缺考/出考率）、`rooms`（按教室合计）、`topAbsent`、`distribution`、`roomHistory`。一场考试 = 同一标题 + 同一考试日期；同一场分几次下发验收（批次）时，人数累加，`rooms`（教室数）和教室的 `exams`（考试次数）去重。`exams[]` 每项含 `rooms`（去重教室数）、`batches`（批次数）、`records`（入库记录数）、`expected/actual/absent/rate`；`totals.reports` = 记录总数。出考率分档按未舍入的 实到/应到 计算，应到为 0 的教室不进分档。

- **前台只填报**：没有管理员入口、验收、改标题、改数据、导图，也没有密码框；标题/日期是下发时定的，页面只读显示；教室名单与机构名来自 `GET /api/site`。提交即最终，填错只能由管理员在后台改（`PUT /api/admin/current-reports/<教室名>` 或数据页明细）。
- **验收在后台**：数据页「当前场次」条上的「验收并结束本场」，二次确认（列出已填/未填教室），不再输入密码。
- **导图（竖版 A4）**：数据明细每行「导图」、详情里「导出图片」。版面一律是**先列每间教室，最后是全部汇总**（教室数、应到/实到/缺考合计、总出考率）。≤30 间单列表格，31–100 间自动两/三列，更多用紧凑格子（教室名 + 实到/应到，出考率低于 80% 的格子标淡红）；字号按最长教室名实测宽度自适应，名字不截断。后台配置上限 500 间（默认名）都能在一张 A4 图片里看清；**一张 A4 看不清时（例如导入的历史数据有上千间）自动改为导出 HTML 网页**，同样先单间后汇总，浏览器打开即可，打印自动分页。抬头和页脚的机构名/地址取自「基本信息」。可视化图表不导出图片，在页面里看。

## 5. 教室识别规则（按访问 IP）

教室号 = 访问 IP 的**某一段**。可配置「第几段」+「前缀」：**默认第 3 段、前缀留空（不限网段）**，例如 `192.168.7.25` 就是第 7 间；如果服务端同时被别的网段访问，可以把前缀设成本单位教室的网段（例如 `192.168.`），只有这个网段才认教室。

- 段值必须落在 1–N（N = 后台「基本信息」里配置的教室数量，默认 30，最多 500）才算一间教室；名单默认按数量自动生成「一教室…N教室」，也可手工指定每间教室的名称。**有未验收的数据时不能修改教室数量/名单**（接口返回 409），请先验收。IP 不符合规则时识别不到，填报页让用户手动选教室（与原行为一致）。
- 设置里有**实时预览**（输入一个 IP 看对应教室），以及「按已登记客户端自动推荐」：用已连接客户端的 IP 反推哪一段最像教室号并一键套用。
- 转发头（`X-Forwarded-For` 等）**只在连接来自本机回环时才信任**，避免被伪造成别的教室。

## 6. 场次与下发（核心业务流程）

场次状态只有两种：**开放**与**关闭**。

- 管理端「下发」：填弹窗内容（默认「请点击确定填写缺考信息」）、**标题（必填，是统计表的表头，每次下发都要填）**、考试日期（可选，默认当天），选「立即」或「定时」。标题和考试日期归下发所有：前台不能改，老师在填报页填的标题/日期一律不算数。如果下发时还有未验收的数据，统计表表头沿用当前场次的标题；**立即下发**时本次填的标题/日期没被采用，接口返回 `titleKept: true`，后台会提示（填的与当前场次相同则为 false；定时下发不返回该字段）。**定时以服务器时间为准**（页面上显示服务器当前时间），客户端本机时钟不参与任何决策。
- 下发触发时场次变为**开放**；在线客户端 ≤2 秒内弹窗，点「确定」后自动用 Chrome 打开填报页。客户端离线时错过的弹窗，**重连后只要该教室还没提交就会补弹**。
- 管理员在后台**验收**（`POST /api/admin/accept`，需已登录后台）后场次变为**关闭**：任何人再访问填报页只看到「当前暂无可填报场次，请联系考务管理员」，服务端接口也拒绝提交（返回 409，不只是前端隐藏）。
- 验收时仍处于等待中的定时下发保持等待，到点照常触发（用于下一场）。服务停机期间错过超过 10 分钟的定时下发标记为「已错过」，不会补发。
- 从旧版本升级的库：有未验收数据则视为开放，否则关闭。

## 7. 备份、导出与导入

- 自动备份：默认开启，每 3 天一次，保留 90 天（面板可改）。无任何备份时启动后立即做第一次。
- 手动：面板「立即备份」「导出到…」「从文件导入…」。导入前会**先校验文件**（必须是完整的 SQLite 且含 `absence_reports` 表）并**自动备份现库**，校验失败现库不变。
- 备份/导出/导入均使用 SQLite backup API，运行中也能得到一致的副本；导入不替换文件，兼容 WAL。
- 这三类操作都会写入「系统操作日志」。
- Excel 导入前的自动备份同样走 backup API（不再直接复制运行中的数据库文件）。

cd client && go vet ./... && go test ./...                                         # 客户端逻辑

## 9. 必须在真实 Windows 上验收的项（开发环境无法覆盖）

- 托盘图标与右键「退出」、Explorer 重启后的托盘恢复；
- 开机自启（重启后客户端自动出现）与崩溃自动重启（结束 worker 进程后 2 秒内重启）；
- Chrome 实际被拉起并打开填报页；高 DPI 下弹窗尺寸与前台置顶；
- tkinter 控制面板在 Windows 上的显示、`os.startfile`、`.bat` 脚本；
- **未签名的 exe 可能被 Defender/杀毒软件拦截或误报**（自注册自启 + 自拉起的行为很像木马）。需要把客户端和服务端目录加入信任，或后续做代码签名。

## 10. 已知限制

- 明文 HTTP、共享接入密钥，只适用于受信任的局域网。
- 管理员登录没有失败限速。
- 服务端在 Windows 上不设置 SO_REUSEADDR（Windows 下它允许第二个进程绑定到同一个正在监听的端口），所以重复双击启动会得到「端口已被占用」提示而不是悄悄起两个服务；Linux 上保持原行为。
- 打包成单个服务端 exe（`build_server_exe.bat`）尚未在 Windows 上实际打包验证；路径约定已由测试钉住：打包后 `data/`、`backups/`、`client/dist/` 都在 exe 所在目录（不在退出即删的临时解压目录），`static/` 读自包内。默认以「源码目录 + 系统 Python」方式运行最稳妥。
