# 迭代计划

## 第一阶段：文档和业务闭环

目标：明确系统边界，完成最小可用版本。

- 建立项目文档。
- 确认技术栈。
- 创建前端填报页面。
- 创建服务端提交接口。
- 创建数据库表。
- 实现缺考人数和出考率服务端计算。
- 实现提交成功提示。

验收标准：

- 普通用户可以打开页面填写并提交。
- 数据能保存到数据库。
- 缺考人数和出考率计算正确。

## 第二阶段：管理员后台

目标：管理员可以查看汇总和历史数据。

- 实现底部管理员入口。
- 实现管理员密码登录。
- 实现后台列表页。
- 实现汇总统计。
- 实现日期筛选。
- 实现标题模糊搜索。
- 实现记录详情查看。

验收标准：

- 管理员登录后可以看到上报明细。
- 汇总数据与明细数据一致。
- 日期筛选和标题搜索可用。

## 第三阶段：体验和样式打磨

目标：让系统更适合现场快速使用。

- 优化普通填报页面布局。
- 优化移动端和桌面端显示。
- 优化后台表格密度和筛选体验。
- 增加加载、空状态、错误提示。
- 优化表单校验提示。

验收标准：

- 普通用户能快速完成填报。
- 管理员能快速定位数据。
- 主要页面在常见屏幕尺寸下不拥挤、不遮挡。

## 第四阶段：数据管理扩展

目标：提升实际考务使用能力。

- 导出 Excel。
- 打印报表。
- 记录编辑或更正。
- 防重复提交策略。
- 数据备份。
- 管理员密码修改。

验收标准：

- 管理员可以导出筛选结果。
- 关键数据有备份或恢复方案。
- 管理员可以处理误填数据。

## 第五阶段：高级能力

根据实际使用反馈决定是否实现：

- 多管理员账号和权限。
- 结构化缺考学生名单。
- 按学生、班级、科目维度统计。
- 批量导入考试场次。
- 统一身份认证。
- 外网或跨校区访问。
